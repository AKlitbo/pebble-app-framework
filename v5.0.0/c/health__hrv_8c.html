Detailed Description

The heart rate variability half of the health store.

The watch reports one gap between two heartbeats at a time, as a health event. The health store holds the app's one health subscription, so it hands each of those events here, along with its turn on the face's cadence. The arithmetic, which beats count and how a run adds up to RMSSD, is in core/health/hrv_run.c, and the movement score is in core/health/hrv_motion.c.

◆ cannot_count()

bool cannot_count ( void )
static

Whether the burst being held can no longer count for the main reading.

Steps never come back off within a burst, so a walk decides it at once. The still level also gives up once the wrist has moved more than a whole burst at the limit could hold, rather than as soon as the average crosses it, since a scratch early on does not mean the burst will not pass.

◆ hold_start()

void hold_start ( uint32_t now_sec)
static

Holds the sensor on for the burst that just started, so its run can fill.

The watch turns the sensor off on its first good heart rate, which is only a handful of beats in. A period shorter than the sensor's warm up keeps it on, so the burst is asked for at HRV_HOLD_PERIOD_SEC until its run is done. That costs up to HRV_HOLD_MAX_SEC of sensor time a burst, and is what gives a run its 20 beats at all.

Parameters
now_secThe time now, in seconds.

◆ save_log()

void save_log ( void )
static

Saves the log to flash, when the face gave it a slot.

It runs once a reading, which at a five minute period is a few hundred writes of a quarter of a kilobyte a day. The CPU is already awake for the burst, and a log saved only when the face closes would lose the day whenever the watch resets.
