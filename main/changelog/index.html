Changelog

All notable changes to the Pebble App Framework are documented in this file. Each version lists the framework changes a face developer has to know about first, then the wearer-visible changes, the ones someone wearing any face built on it would see without the face changing its code.

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

6.1.0 - 2026-11-11

Framework Changes

Added

  • Added stockInstance and STOCK_SOURCE in ts/plugin-app/stocks.ts, which serve StockQuotes from a plugin app as finance/stock in the text Pebble's own Stocks plugin uses.
  • Added pluginRequest and fetchText in ts/plugin-app/request.ts, the framework's request on the plugin runtime's fetch, for a plugin app to fetch with the framework's providers. PluginPebble gains permissions.query.
  • Added fetchQuotes and roundStamps in ts/stock/quotes.ts, and parseSymbols(raw, max) in ts/stock/symbols.ts, so a plugin app fetches quotes and keeps a provider's quota the way the stock feature does.
  • Added FREE_PLANS and onPaidPlan in ts/stock/limits.ts, each stock provider's free plan in one place, and allowance, keepSent, loadLedger, and saveLedger in ts/stock/ledger.ts, which count the calls sent against it.
  • Added rateLimitWait, roundWait, and currentTradingDay to ts/stock/schedule.ts, and util.rateLimit and util.bodyless to ts/stock/util.ts. shouldThrottleStockFetch takes a rate limit's retryAtMs after now.
  • Added a Paid Plan toggle for the stock settings, on STOCK_PAID_PLAN. Pass stocks: { paidPlan: true } to buildConfig and declare the key. With it on, the phone drops the free plan's floors and counts for a keyed provider, and shouldThrottleStockFetch takes a paid argument for the same.
  • Added the PLUGIN_STOCKS define, which reads stock quotes from a Pebble app plugin serving finance/stock. The build adds STOCK_STRIP and STOCK_REQUEST, and STOCK_PROVIDER unless providers.stocks is ["plugin"]. A face that lists providers.stocks puts plugin in it. The plugin source schema on key 249 moves to version 2, and an older blob reads in with the stock choice on its default.
  • Added name, currency, and asOfEpoch to StockQuote, filled from Yahoo and Twelve Data where they send them, and the quote time from Finnhub. A RATE LIMIT quote carries limit, the second, minute, or day limit the provider named.

Changed

  • A page with a WEATHER_API_KEY or STOCK_API_KEY row beside its WEATHER_PROVIDER or STOCK_PROVIDER select now keeps a key for each provider. prepareSettingsPage runs for such a page even when no feature brings a page hook, and the page gains a hiddenStore row on PF_PROVIDER_KEYS, which a face's customClay sees in getAllItems. PF_PROVIDER_KEYS and the pf-provider-keys localStorage key are reserved, so a face uses neither.

Wearer-Visible Changes

Changed

  • Switching the weather or stock data source now shows that provider's own API key. Switching back no longer needs the key pasted again, and switching no longer hands one provider another provider's key. A key saved before the update stays with the provider saved beside it, and one left under a provider that needs no key, such as Yahoo, goes to the first provider picked that needs one.
  • A quote that timed out now shows TIMEOUT rather than NET ERROR, since the call may have reached the provider. The phone then waits for the provider's next fetch rather than asking again at once.

Fixed

  • Fixed a gap under every dropdown on a plugin app's settings page in the Pebble Android app. The page now carries the same style rules a watchface's page does.
  • Fixed Finnhub showing INVALID KEY for a ticker its free plan does not cover, such as ^GSPC, while the same key priced the others. It now shows NO ACCESS.
  • Fixed Alpha Vantage showing RATE LIMIT in most slots until the next evening. Its free key refuses calls closer than a second apart, so the phone now asks for one ticker at a time, 1.1 seconds after each answer, and asks again only for the tickers it was refused.
  • Fixed a settings save under Alpha Vantage spending a call for every ticker. It now asks only for tickers without a current quote.
  • Fixed a RATE LIMIT replacing the last good quotes on the watch. A refused slot keeps its last price. Twelve Data asks again after the next clock minute, or after midnight UTC for its daily limit, and Finnhub and Yahoo wait 15 minutes, doubling up to two hours.
  • Fixed Twelve Data and Alpha Vantage going past their free plans' limits after quick saves, a restart partway through a fetch, or a rate limit with no explanation from the provider. The phone now counts every call it sends, and holds Twelve Data to 8 a minute and 800 a day and Alpha Vantage to 25 a day.
  • Fixed Finnhub and Yahoo fetching twice on some launches. The phone now leaves 45 seconds between their fetches.

6.0.0 - 2026-11-10

Framework Changes

Added

  • Added plugin apps, Pebble app plugins with no watch code. Set "projectType": "plugin" and the SDK's plugin block in the appinfo, and paf build bundles src/plugin/index.ts into plugin.js with esbuild and runs pebble build with the SDK's plugin wscript. Building one needs Pebble SDK 4.44 and pebble-tool 5.1.2. prepare-release and publish-release accept a plugin app and name its asset <target>-<version>.pbw. docs/how/plugin-apps.md covers the rest.
  • Added a Clay settings page for a plugin app, built from the clayConfig that src/config/index.ts exports when the appinfo sets "configPage": "config.html". handleSettings and readSettings in ts/plugin-app/settings.ts answer the page and read the settings on the plugin side. paf tool <plugin app> clay-preview previews the page.
  • Added eventInstance and CALENDAR_EVENT_SOURCE in ts/plugin-app/calendar.ts, which serve CalendarEvents from a plugin app as the standard calendar/event source. Copy CALENDAR_EVENT_SOURCE into the plugin block's sources as written.
  • Added uid and calendar to CalendarEvent, from a feed's UID and from the calendar name a plugin gives. Neither reaches the watch.
  • Added the PLUGIN_WEATHER, PLUGIN_CALENDAR, PLUGIN_MUSIC, and PLUGIN_PHONE defines, which read the weather, the calendar, now playing, and the phone's battery from Pebble app plugins. Set the define in the appinfo's defines, and the build adds the message keys and permissions it needs. For now playing and the battery, also pass music from ts/music/feature or phone from ts/phone/feature to startPebbleApp, and read them on the watch from music_store and phone_store. The pkjs build carries the plugin code only for the kinds a face turns on.
  • Added providers to the appinfo, beside defines, to name what a face offers for each kind of data, as in "providers": { "weather": ["plugin", "openmeteo"], "calendar": ["plugin"] }. The first custom provider listed is the default, a kind left out keeps every provider, and calendarHosts names the hosts a face's iCal feeds come from. usesPermissions then lists only the sites the listed providers call. The build stops on a list it cannot use, and warns a plugin only weather face that declares LOCATION_NAME. Mark its location search with pluginSourceHides: 'WEATHER_PROVIDER', or list open-meteo.com in its own usesPermissions.
  • Added the pluginSource, pluginSourceHides, pluginSourceLead, and pluginSourceRows marks on ClayConfigItem, and hideWhenEmpty on a section. Mark a face's own weather or calendar rows with pluginSourceHides so they hide while the plugin is picked, and its own line about choosing a provider with pluginSourceLead.
  • Added the page, seeded, and settingsUnanswered hooks and the components list to FeatureHooks, and providers to FeatureContext.
  • The watch now keeps the wearer's weather and calendar source choice through a reinstall of the Pebble app, in a settings schema of the framework's own under persist key 249, SETTINGS_PLUGIN_SOURCE_KEY. Leave that key free in every face. A face that keeps the choice gets SETTINGS_REQUEST and SETTINGS_FRESH from the build, and calls settings_init(NULL) when it has no settings of its own. The build writes the defaults from providers as PLUGIN_SOURCE_WEATHER_DEFAULT and PLUGIN_SOURCE_CALENDAR_DEFAULT, so a face cannot set either in its defines. The first launch that keeps a choice counts the watch as fresh, so the phone restores the settings once. Say so under Notes in the face's own changelog.
  • A face built with PLUGIN_WEATHER and no WEATHER_TEMPERATURE_UNIT key now gets its weather in the unit the wearer picked in the Pebble app. readout_weather_temp then writes the temperature with no unit letter.
  • Added plugin only weather for a face with no settings page of its own. Pass clayConfig: [] to startPebbleApp and list "providers": { "weather": ["plugin"] }.
  • Added the supported plugins panel, which lists the plugins each of a face's kinds can read from, with links to their appstore listings, at the foot of the settings page of a face built with a plugin define.
  • Added --plugins=<file> and --out=<file> to clay-preview, to open the page on a phone with the plugins the file lists and to write the page to another file.
  • startPebbleApp now logs a warning at startup when a face's customClay is not written as a function, since Clay hands it the page as this and an arrow cannot take that.
  • Added the --pf-accent, --pf-on-accent, --pf-surface, --pf-ink, and --pf-line custom properties, which colour the location search and the supported plugins panel, and a keyboard focus ring on both. Set them on :root from the face's own component CSS. Each falls back to Clay's own colour.
  • Added WxCond and wx_cond_parse in c/core/weather/wx_cond.h, which turn the condition token into a number from WX_COND_CLEAR to WX_COND_STRM, or WX_COND_UNKNOWN. WX_COND_EACH(X) hands each condition's name to a face's macro, so an art table built from it stops the build when a new condition has no art.
  • Added hrv_settle_gaps to HealthConfig, the beat gaps the store leaves out at the start of each HRV burst while the sensor settles. 0 keeps the default of 10, and health_store_hrv_settle_gaps gives the count in use.
  • Added uv_band in weather/uv_band.h, which gives the WHO risk band a UV index falls in, with uv_band_name and uv_band_short_name for its full and short names.
  • Added health_store_has_hr and HEALTH_HR_SENSOR, which say whether the watch has a heart rate sensor, going by the platform.
  • Added fonts_load and fonts_swap beside fonts_register, which load a font into a slot and swap a slot to a new one. Call fonts_swap only where the face rebuilds its layers straight after, since a TextLayer keeps the freed font.
  • Added readChoice and readFahrenheit in ts/pkjs/settings-store.ts, which read a saved select or radio group, and the temperature unit, whether Clay saved it as text or as a number.
  • paf build now loads the face's settings page before pebble build and writes page/settings_page.h into each sandbox, with the page's counts and defaults for the watch. The waf build stops on a header that does not match the sandbox, so build with paf build rather than pebble build in a sandbox.
  • Added SETTINGS_COUNT(KEY), SETTINGS_COUNT_CHECKED(KEY, table_count), and SETTINGS_DEFAULT(KEY) in settings_catalog.h, the page's option count and default on a message key, for a face's own fields. SETTINGS_COUNT_CHECKED stops the build when the page's count differs from the face's table.
  • Added store_poll_start and store_poll_reconnect to io/stores/store_poll.h. A face's own polling store calls store_poll_start from its init in place of store_poll_set, and store_poll_reconnect says whether it should ask again when the phone comes back.
  • Added KNOWN_WIND_UNIT(off) and SETTING_WIND_UNIT for the wind speed unit, and wind: {} on buildConfig and weatherSection for its select, with WIND_UNIT_OPTIONS in config-rows.ts for a face's own weather section. Declare WEATHER_WIND_UNIT in messageKeys and build with --clean.
  • Added notIn on a visibleWhen condition, the values that hide a row.
  • Added messageKeys to Feature, the message keys a feature needs, which paf build adds to a face's own.
  • Added system_store_remove_link_listener beside system_store_add_link_listener. A face's own store that listens for the link calls it from an init that starts the store with live false.

Changed

  • Breaking: The build now refuses a projectType in a face's appinfo other than plugin or native. Set it to one of those, or take it out.
  • Breaking: SettingsSchema.min_versioned_size is now first_size, set with SETTINGS_BLOB. Replace a schema's .blob, .blob_size, and .min_versioned_size lines with SETTINGS_BLOB(s_settings, 25). The number is the struct's size in bytes in the blob's first release, written as one plain number. docs/how/settings-on-the-watch.md covers finding it.
  • Breaking: KNOWN_THEME(off, table_count) and KNOWN_HEADER_FONT(off, table_count) now clamp to the count on the settings page, and stop the build when it differs from the face's own table. Pass the size of that table, such as THEME_COUNT. Delete the count argument from KNOWN_STEPS_MODE, KNOWN_DISTANCE_UNIT, KNOWN_TIME_FORMAT, KNOWN_BLUETOOTH_VIBE_CONNECT, KNOWN_BLUETOOTH_VIBE_DISCONNECT, KNOWN_HOURLY_VIBE, and KNOWN_BATTERY_DISPLAY.
  • Breaking: health_store_set_hrv_rules now takes the settle count as its third argument, after walk_steps. Pass 0 there for the default of 10 gaps.
  • Breaking: Every settings page now registers a pafPageStyle component, so a face cannot register one of that name. Its style repeats Clay's own row padding at .section > .component.component-X, so a face rule that sets that padding at Clay's weight, such as .section .component-select, now loses. Write it at .section > .component.component-select or higher. A face component that borrows one of Clay's row classes, such as component-button, now takes Clay's padding for that row on every page.
  • Breaking: A face's customClay now runs after the framework's own page code rather than replacing it. Drop the code that shows and hides visibleWhen rows from a customClay, or drop visibleWhen from those rows to keep its own rules.
  • Breaking: The settings page's own classes now start with pf-. .theme-preview is now .pf-theme, .tp-* is .pf-theme-*, .gl-store is .pf-hidden-store, and .loc-* is .pf-loc-*. Rename them in the face's page styles and code, since a missed rename still builds and passes every check. A storeClass the face passes keeps its name.
  • Breaking: weather_store_cond now returns an empty string for a reading with no condition, where it returned --. Check for an empty string in place of --.
  • Breaking: Add SETTINGS_FRESH to messageKeys beside SETTINGS_REQUEST and build with --clean. The watch uses it to tell the phone it lost its settings, so the phone puts the wearer's settings back after a reinstall. The build refuses either key without the other. A face with no settings of its own can leave both out. The build adds both for a face that keeps a plugin source choice.
  • Breaking: Pass the weather feature beside any weather extra, forecast, or air key, such as WEATHER_HUMIDITY or WEATHER_FORECAST_DAILY, or take those keys out of messageKeys, and build with --clean. The build now refuses them without the four base weather keys, and stops on a key group declared in part, such as LOCATION_LATITUDE without LOCATION_LONGITUDE.
  • Breaking: KNOWN_DATE_FORMAT(off) no longer takes a default. Delete the second argument. Every KNOWN_* entry now takes its default from the settings page, so set the page's default to the one a fresh watch should show.
  • Breaking: paf build now stops on a settings page default the watch would get wrong, such as one that is not among its options, and on an option past the count the watch holds for a shared setting, naming the face and the key. Change the page's default to one the watch can hold, and take such an option off the page.
  • Breaking: paf build now stops on a page control whose messageKey the appinfo does not declare, a _REQUEST key no feature answers, and a customClay not written with the function keyword. Declare the key or take the control off the page, pass the feature that answers the request or take its key out, and write customClay as function customClay() { ... }.
  • Breaking: paf build now stops when the face's own WEATHER_PROVIDER or CALENDAR_SOURCE picker does not offer, or does not open on, the default it writes from providers. Offer the provider in the picker, or list the one it opens on first in providers.
  • Breaking: paf build now adds the message keys a face's features and plugin defines need, and fills in sdkVersion, enableMultiJS, and the location and configurable capabilities. Delete them from the face's appinfo and build with --clean once. A key the face still lists keeps its place. build-manifests.ts now takes only --targets <face>.
  • The phone now sends the watch its settings when the settle at launch rewrites a saved provider the face no longer lists, so a later restore from the watch brings back the settled provider.
  • Breaking: Only a store's init now decides whether it is live, so a store started with live false stays seeded through every reconfigure. Pass live = true at init for any store that has to start later, with poll_min 0 for a polling store, or with minute_tick, beats, and hourly all false for a clock, so it waits for the reconfigure.
  • Breaking: Dev mode is now a build flag. Build with paf build <face> --dev, and commit the harness in a paf.dev.config.json beside the unit's paf.config.json, such as { "walk": "themes", "clock": "08:00" }. The unit still lists "dev": {}. Delete any DEV_MODE, DEV_TIME_HOUR, DEV_TIME_MIN, or DEV_TAP_WALK_<NAME> a face defines itself, with any dev/dev_walk.h include or walk mode macro of its own, and include the plugin's dev/dev_hooks.h in place of a face's own dev_seed_stores, dev_start, dev_stop, or dev_force_time declarations.
  • The provider pickers on the settings page now offer only the providers a face lists. A picker left with one provider is dropped, and a plugin only kind loses its picker and its custom rows. A saved provider the face no longer offers is rewritten to the default at launch. When a face moves weather or the calendar to ["plugin"], say so under Notes in its own changelog, since that deletes the wearer's saved city and API key, or the iCal link.
  • The location search's notes now take their colours from --pf-note-accent, as the plugin notes do.
  • dev_walk_seed_stores now also starts the stock, calendar, phone battery, and now playing stores seeded and empty on a face that declares STOCK_STRIP, CALENDAR_STRIP, the phone battery keys, or the now playing keys. A face that seeds one of those stores itself calls that store's init after dev_walk_seed_stores. Its weather seed now follows the wearer's temperature unit.
  • system_store_add_link_listener now also exists on a face that declares WEATHER_REQUEST, STOCK_REQUEST, or CALENDAR_REQUEST, and its list keeps one slot spare for a listener of the face's own.
  • The framework now registers hiddenStoreComponent for a page that holds a hiddenStore row, so a face can drop it from components.
  • A page from buildConfig, weatherSection, or stocksSection with weather or stocks now carries the framework's show and hide code, dependentVisibility, for its API key row's visibleWhen.
  • createClay and prepareSettingsPage now add Clay's own input or select style to a page with a location search or theme picker and no text box or dropdown of its own, unless the face passes its own. A face rule on those fields lighter than Clay's own rules now loses.

Removed

  • Breaking: Removed serializeValueAs from ClayConfigItem. Delete it from any select, radio group, or input. The watch reads a choice sent as text or as a number.

Fixed

  • Fixed a weather, stock, calendar, location, or system store seeded with live false after a live start showing real readings over its seed, as in a screenshot build.
  • time_store_reconfigure now does nothing when the new TimeConfig runs the same tickers, so a settings save no longer runs an extra tick and repaint. TimeConfig now lives in clock/time_config.h, which time_store.h still brings in.

Wearer-Visible Changes

Changed

  • The weather, stocks, and calendar now catch up as soon as the phone comes back after being away, rather than at the next scheduled refresh. The stores do it themselves, so a face that asks for these readings from its own system_store_on_reconnect callback can delete that code.
  • The settings page's opening line now mentions the weather when the page has a Weather section and the face has no opening line of its own. buildConfig picks the line.

Fixed

  • Fixed the settings page showing an API Key box under Open-Meteo and Yahoo, which need no key. The key rows from weatherSection and stocksSection now hide for those providers.
  • Fixed a setting picked from a dropdown doing nothing on the watch when the watch keeps it as an on or off switch. The watch now takes a toggle sent as the text "0" or "1". settings_apply_inbox reads it through tuple_number_or in c/pebble/io/tuple_read.h.
  • Fixed the location and time zone searches finding nothing on Android with plugins on when the face has no built-in weather. usesPermissions now lists open-meteo.com for a CLOCK_TIMEZONE_ key, and for LOCATION_NAME unless providers.weather is ["plugin"], which gets a warning instead.
  • Fixed the stock strip keeping another source's quotes until the next day after a settings restore changed the stock source. The stock cache now starts fresh when the provider changes.
  • Fixed the settings page showing extra space under and beside its controls in the Pebble Android app with plugins on.
  • Fixed the location search showing as a plain white box, and the theme picker as a bare dropdown, on a settings page with no other text box or dropdown.

5.0.0 - 2026-11-05

Framework Changes

Added

  • Each target's package.json now carries usesPermissions, worked out from the face's message keys. WEATHER_REQUEST adds Location and the weather providers' sites. STOCK_STRIP adds the stock providers' sites, and CALENDAR_STRIP asks for any site, since a feed can live anywhere. SDK 4.42.0 and later build every pbw as manifestVersion 2, and the Pebble app then holds the phone code to this list whenever the wearer has plugins on. A face that fetches from a site of its own lists it in its appinfo's usesPermissions, and its sites join the generated Internet entry.
  • Added heart rate variability to the health store. Set "HEALTH_HRV": 1 in the appinfo's defines and give HealthConfig an hrv_period_sec, and health_store_hrv_ms and readout_hrv give the reading as RMSSD in ms. Each burst holds the sensor on until its run of beats fills. Only the Pebble Time 2 reports beat gaps, so elsewhere health_store_hrv_sampling is false and the reading stays at none. Without the define the getters answer none and the face carries none of the code.
  • Added still, busy, and walking to each HRV burst. Steps through the burst decide walking, from hrv_walk_steps, and the accelerometer's movement score splits still from busy, from hrv_still_mg. hrv_count takes an HrvCount for which bursts become the reading, and health_store_set_hrv_rules changes all of these when a setting does. The store reads the accelerometer's data service while a burst is held, so a face that reads that service itself cannot use HRV.
  • Added the HRV log. health_store_hrv_log gives the latest 24 readings with what the wearer was doing, today by the hour, and the night's average, read with the functions in health/hrv_log.h. Give HealthConfig an hrv_persist_key to keep it across launches. health_store_hrv_recent, health_store_hrv_live, health_store_hrv_still_mg, and health_store_hrv_walk_steps give a tuning panel each burst's numbers and the limits in use.
  • Added health_store_deinit. Call it from the face's deinit. With HRV on it stops the request for beat gaps, which the watch otherwise keeps going for an hour after the face closes.
  • Added HEALTH_HR_DAY, a health store part named as .hr_day = HEALTH_HR_DAY. The store keeps today's heart rate by the hour, filled from the watch's minute log at launch and from each reading after, and health_store_hr_day hands it back to read with hr_day_hour_avg and hr_day_stats from health/hr_day.h. HealthSeed.hr_day pins a day for screenshots.
  • Added subheading in ts/pkjs/config-rows.ts, a smaller heading for a group of rows inside a section, and size on ClayConfigItem for a heading row.

Changed

  • Breaking: The framework now needs SDK 4.44 or later, and a build on an older SDK stops at configure. 4.44 is the first SDK pebble sdk install offers that builds manifestVersion 2. src/toolchain.json records SDK 4.44 and pebble-tool 5.1.2 for setup-pebble and paf doctor. Run pebble sdk install 4.44, or pebble sdk activate 4.44 when it is already installed. Then run uv tool install --force pebble-tool==5.1.2 and rebuild with --clean. SDK 4.44 stamps its apps with SDK version 5.110, and a watch turns away an app stamped newer than its own firmware, so a face built with it needs watch firmware 4.44.3 or later. On older firmware the watch lists the face as incompatible until it updates.
  • Breaking: health_store_hr_history now returns const uint8_t *, the same as health_store_step_hourly, since only the store writes its heart rate window. Hold what it returns as a const uint8_t *.
  • Breaking: HealthConfig.hr_history and step_history now take a part rather than a bool. Pass .hr_history = HEALTH_HR_HISTORY and .step_history = HEALTH_STEP_HISTORY for the charts the face shows. A face that leaves one out no longer carries its code or its buffer, and a HealthSeed curve for a part the face does not name is not taken.
  • Breaking: copy_bounded, cstring_is_clean, and cstring_setting_is_clean are now declared in text/cstring_fit.h rather than text/number_format.h, beside the other helpers for text in a fixed buffer. A face calling one includes text/cstring_fit.h.
  • report-memory now reads the full 24-bit static size from a header at version 0x10.0x01, and render-memory measures each row against its own platform's limits from the SDK. Emery and gabbro rows are measured against 128 KB for both the app image and the static size, where they were held to 64 KB. The older platforms stay at 64 KB, and aplite's static size is measured against its 24 KB.

Removed

  • Breaking: Removed WeatherOpts.place and the WeatherAPI provider's place-name lookup. Pass coords to a provider called directly, since WeatherAPI given only a place now answers No Location. The weather feature always passes coords, so a face using it needs no change.
  • Breaking: Removed labelShort from ConditionEntry and ConditionFallback. Nothing read it, since the watch's wx_label_short shows the token itself. Take it out of a face's own condition rows.
  • Breaking: Removed layout/layout_role.h with layout_role_pick, LayoutRole, and the LAYOUT_ROLE_* constants. Include role/role.h and call role_pick, which takes the same arguments. LayoutRole becomes Role, and LAYOUT_ROLE_DAY becomes ROLE_DAY, and likewise for NIGHT, QUIET, and COUNT.
  • Breaking: Removed the wi, ux, and sr keys at the start of an icon's svg in resources/icons.json. Every name is now read as a path from the sources folder. Write the folder in place of the key, so wi/wi-day-sunny becomes weather-icons/svg/wi-day-sunny, ux/ becomes uxwing/, and sr/ becomes svgrepo/. A name left on a key reads as a missing SVG, so the icon keeps its PNG with a warning, and a run where every SVG is missing stops.
  • Breaking: Removed the limit names with MAX in the middle. In C, use ENGINE_SLOTS_MAX for ENGINE_MAX_SLOTS, STOCK_SLOTS_MAX for STOCK_MAX_SLOTS, and CALENDAR_SLOTS_MAX for CALENDAR_MAX_SLOTS. In TypeScript, WIRE_CAPS.FORECAST_MAX_COLS, WIRE_CAPS.STOCK_MAX_SLOTS, and WIRE_CAPS.CALENDAR_MAX_SLOTS become FORECAST_COLS_MAX, STOCK_SLOTS_MAX, and CALENDAR_SLOTS_MAX, and the wire module's default export drops STOCK_MAX_SLOTS. A face that still defines ENGINE_MAX_SLOTS, in its appinfo's defines or in its own C, stops the build with a message naming ENGINE_SLOTS_MAX.
  • The face actions no longer point out an appinfo still in config/, where framework 3 kept it. A face they cannot find now stops with only its name.

Fixed

  • Fixed a health store started again with live false still taking health events. The next heart rate or movement event replaced its seed with a live reading, so a face switching to its screenshot fixture could show real numbers. health_store_init now unsubscribes when it goes from live to seeded, and the first read of the hourly steps queued by a live start no longer lands on the seed.

4.6.0 - 2026-10-16

Framework Changes

Added

  • A themePreview config item takes an optional previewsByKey, the messageKey of another control on the page. Its previews then nest, keyed first by that control's value and then by the option's value, so the shots drawn under the picker follow a second choice on the page such as a scene or a mode. One picker still owns APPEARANCE_THEME, so the value saves the usual way. The named control is read once the page is built, and the preview redraws whenever it changes.

4.5.0 - 2026-10-15

Framework Changes

Changed

  • The theme picker can show a different preview per platform, so a face built for more than one watch shows each watch its own shots. A theme-previews.json value can now be a map keyed by platform, { "emery": <path|list>, "gabbro": <path|list> }, as well as the path or list it already took. paf gen <face> theme-previews writes the map through to theme-previews.g.js, and the themePreview component reads the watch the settings page was opened from and draws that platform's shots. A platform name has to be one Pebble builds for, so a typo stops the generator. A flat value is unchanged, and a theme whose map leaves out the watch in hand falls back to any shots the map carries. A shot a map names for a round watch is masked to the circle the screen shows, since a round watch's screenshot is a square framebuffer with the corners outside the circle. A flat value names no platform, so it is left square.

2.0.0 - 2026-09-17

Framework Changes

Added

  • Added node-version and sdk-version inputs to the setup-pebble action. Both are optional and default to Node 24 and the latest SDK.
  • Added report-memory and render-memory actions, which rank each face's memory use in the CI run summary.
  • Added prepare-release and publish-release actions for checking and publishing face releases.
  • Added an optional cancel callback to the builder's DragSpec, called when a pointer is taken away mid-drag. Builders that remove an item from their model in lift can restore it here.
  • Added createDedupedSender to ts/pkjs/send-queue.ts. It wraps a queueSend so an unchanged payload is skipped and a payload whose send failed is not counted as delivered, which is what the weather, stock, and calendar pushes all use now.

Changed

  • Breaking: The engine can now be mounted under any folder name. The face repo declares that folder in its package.json workspaces, which is how the tools locate the engine.
  • build.sh and the waf build now find faces through the same lookup as the other tools. build.sh no longer needs the repo's build:pkjs script.
  • Breaking: Stocks and iCal are now opt-in features. Pass features: [stocks, calendar] to startPebbleApp. Faces that omit them no longer bundle their code, so Gridlock must list both.
  • Breaking: The Clay, thumbnail, and icon generators now take the face as an optional argument and run for every face that needs them when it is omitted. A repo now needs one gen:clay, gen:thumbnails, and gen:icons script instead of one per face. Their banners name those scripts, so committed output must be regenerated.
  • ical.js is now copied into a face's build only when the face uses iCal.
  • Breaking: The thumbnail generator now takes panel sizes from the face instead of a fixed list. A face exports them as thumbnailSizes from module-meta.ts.
  • Exported the option and state types used by startPebbleApp, runWeatherRound, buildConfig, the hidden store component, and the WeatherAPI provider so faces can name them in their own code.
  • Pinned @rebble/clay to 1.1.0, which adds the TOUCH, SPEAKER, and RGB_BACKLIGHT capabilities and integer values for inputs, selects, and radio groups.
  • The setup-pebble action now verifies that pebble-tool runs and adds the pebble-tool and SDK versions to the job summary. A pinned sdk-version is cached between runs.
  • Breaking: A locationsearch field now persists the saved place as JSON for every key type, including its timezone alongside the coordinates. The pkjs side builds the offset,label value sent by a timezone field, so a face reading the setting from the phone's config now receives the JSON blob instead of the pair.
  • Breaking: LocationConfig now carries a persist_key, like every other store's config. Pass the key you want location_store_init to save the last fix under. A face that omits it gets key 0, and 253 is what earlier versions used.
  • The strip caps and marker values the phone and the watch both bound against are now generated into c/core/wire/wire_caps.g.h from WIRE_CAPS in ts/pkjs/wire.ts, rather than defined once per language. npm run build:conditions writes it alongside the weather tables, and it is committed like them.
  • The OpenWeatherMap provider now fetches its own endpoint and the Open-Meteo extras at the same time instead of one after the other. A weather round spends one request timeout rather than two, and the extras call goes out even when the OWM key is rejected.

Removed

  • Breaking: Removed the tools/ci/ scripts. A face repo moving to this engine should switch its workflows to the new actions in the same commit.
  • Breaking: Removed weather_store_location_name and the weather store's LOCATION_NAME handler. Nothing read them. STORE_TAG_WEATHER moves to 0x12 with the struct, so a saved reading is refused once after the upgrade and the weather panels show placeholders until the next poll.

Fixed

  • Fixed a nacked send retrying immediately when another send was queued during its backoff.
  • Fixed a store enabled after startup while disabled not receiving the reply to its poll.
  • Fixed ICON_AUTOTRIM and ICON_TRIM_LOG being impossible to override. They are #ifndef-guarded now, so a face can set either one before including icon_cache.h as the header always claimed.

Fixed

  • Fixed settings replies larger than the outbox being sent partially. They are now skipped unless they fit in full.
  • Fixed deleted calendar events remaining on the agenda. An empty calendar or removed feed now clears them.
  • Fixed a cleared watchlist remaining on the watch and returning on the next launch.
