27// a face has the settings reply when it declares both settings keys. the phone asks for the
28// watch's settings with SETTINGS_REQUEST, and the watch answers with SETTINGS_FRESH to say it booted
29// with nothing saved, so the phone puts the wearer's settings back rather than copying the watch's
30// defaults over them. a face that declares neither never has its settings sent back or restored.
31// one without the other stops the build with the missing one named
32#if defined(HAS_MESSAGE_KEY_SETTINGS_REQUEST) && defined(HAS_MESSAGE_KEY_SETTINGS_FRESH)
33#define APPMESSAGE_HAS_SETTINGS 1
34#elif defined(HAS_MESSAGE_KEY_SETTINGS_REQUEST)
35#error "settings need SETTINGS_FRESH in messageKeys beside SETTINGS_REQUEST"
36#elif defined(HAS_MESSAGE_KEY_SETTINGS_FRESH)
37#error "settings need SETTINGS_REQUEST in messageKeys beside SETTINGS_FRESH"
38#endif

40// a face has weather when it declares all four of these. the watch asks with the first and reads a
41// reading off the other three, so all four are one decision. the ok flag is the one that tells a
42// failed fetch from a reading, and a face without it would show "NO GPS" as a live 0 degrees.

44// some has a typo or a gap, which would otherwise build and go wrong on the watch, so the build
